# 세션 시작

`<이름>`은 브랜치 이름이다(`/`가 있으면 앞부분). 고르기와 기획은 한 턴에 끝낸다. 그래야 이 스킬의 모델(Opus)로 기획한다.

1. `sh scripts/start-check.sh $ARGUMENTS`를 실행한다. 브랜치 확인, 원격 합치기(`docs/convention/git.md`), 설정 키 점검, 검증 루프 보관, 핸드오프 생성, 작업 후보 찾기를 스크립트가 한다. 이 일을 손으로 다시 하지 않는다. 종료 코드가 0이 아니면 출력을 그대로 보여 주고 멈춘다.
   - "원격"에 합친 커밋이 있으면 보고 맨 앞에 커밋 수와 눈에 띄는 변화(다른 사람이 끝낸 마일스톤, 새 도메인 패키지, `db/` SQL 변경)를 한두 줄로 적는다.
   - "검증 루프"가 `보관`이면 기획을 새로 쓰지 않고 그 마일스톤을 이어 간다. 보고 맨 위에 "검증 루프가 <N>회차 실패로 보관돼 있어 이어 갑니다. 기획과 기준 파일은 그대로입니다. 루프를 버리고 새로 기획하려면 `! sh scripts/verify-loop.sh clear` 후 `/start`를 다시 실행하세요"라고 적고, 6번의 `승인` 없이 `/impl`로 이어 가라고 안내한다.
   - 핸드오프는 출력의 "지금 하는 것"과 "다음에 할 것 맨 위"로 본다. 파일 전체를 읽지 않는다.
   - PR 병합 여부는 출력의 "PR"로 본다(`gh`를 따로 부르지 않는다).
2. 작업을 고른다. 사람에게 묻지 않는다.
   - 인자가 있으면 출력에 나온 그 마일스톤.
   - 인자가 없으면 "다음에 할 것 맨 위", 그것도 비면 "대기 맨 위". "기다리는 것"은 고르는 조건이 아니다.
   - "마일스톤 파일이 없거나 형식이 다릅니다"이면 `docs/convention/milestone.md` 절차로 새로 만든다. git 이력에서 되살리지 않는다.
3. "기획 상태: 승인 전"이면 이전 기획을 지우고 그 마일스톤을 `sh scripts/milestone-status.sh <SCR-ID> 대기`로 되돌린다(고른 작업과 같으면 지우지 않고 고쳐 쓴다). 고른 작업과 시작 시각을 `<작업> — 기획 (시작 <YYYY-MM-DD HH:MM>)` 형식의 첫 줄로 적고, `sh scripts/milestone-status.sh <SCR-ID> 진행`을 돌린다. 같은 화면 ID의 절이 여럿이면 세 번째 인자로 제목에 든 글자를 준다.
4. 기획을 "지금 하는 것" 아래에 먼저 쓴다(끊겨도 `/verify`가 읽을 수 있게).
   - 문서는 전체를 읽지 않는다. DMS `search_documents`로 찾아 최신 파일명을 정한 뒤 `sh scripts/dms-fetch.sh <파일명> <SCR-ID>`를 돌려 그 출력만 읽는다. 종료 코드 3(캐시에 없음)이면 `get_download_url`의 링크를 세 번째 인자로 주고 다시 돌린다.
     - 기능명세서: `<도메인>_기능명세서`로 검색.
     - 화면설계서: `<도메인>_화면설계서`(도메인은 기능명세서 파일명 앞부분)로 검색하고, 없으면 `화면설계서`로 검색한 목록에서 고른다. 목록을 보기 전에는 없다고 판단하지 않는다.
   - 기능 ID마다 한 줄: 바꿀 파일, 부를 API(남의 것이면 담당 이니셜), 완료 조건(`명령:` 검증 명령, `화면:` 확인할 동작).
   - 부를 API의 경로와 요청·응답 DTO는 `sh scripts/api-row.sh <기능 ID>`(화면 ID를 주면 그 화면 전체)가 뽑은 행과 DTO 절을 그대로 쓴다(`docs/api/` 파일을 읽지 않는다). 다르게 정하면 그 줄에 이유를 적고, 구현 전에 그 초안을 고치는 것을 기획 항목으로 넣는다.
   - 아직 없는 남의 API는 "가짜 응답으로 먼저 만들고 나중에 연결"과 가짜를 둘 곳을 적는다. 완료 조건은 가짜 응답 기준. 연결은 "다음에 할 것"에 남긴다.
   - 맨 아래 `새 의존성:` 줄. 추가할 라이브러리·버전·이유, 없으면 `없음`.
5. 보고하고 멈춘다. 순서:
   - "설정 키"에 빠진 키가 있으면 맨 앞에 그 줄을 그대로.
   - 마일스톤 파일을 이번에 만들었으면 목록(화면 ID·화면명·상태), "대조" 절, 제외한 기능 ID.
   - 기획. 새 의존성이 있으면 따로 눈에 띄게.
   - 끝에: "기획대로 가려면 `승인`(또는 `/impl`), 고칠 점은 그 내용을 답해 주세요. 다른 화면은 `/start COM-003`처럼 다시 실행하세요."
6. 승인 전에는 코드를 쓰지 않는다. 고칠 점을 받으면 기획을 고쳐 5대로 다시 보고한다. `승인`이라고 답하면 `impl` 스킬을 부른다. 이 스킬에서 직접 구현하지 않는다.

핸드오프는 공개 저장소에 커밋된다. 비밀값과 개인 PC 경로를 적지 않는다.
