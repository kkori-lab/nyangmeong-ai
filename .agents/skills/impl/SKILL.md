# 구현과 검증 루프

`<이름>`은 브랜치 이름이다(`/`가 있으면 앞부분). 구현하고, 별도 에이전트의 검증이 `통과`할 때까지 최대 3회 고친다. 판정은 검증 에이전트만 한다. 이 대화에서 판정 문구를 쓰지 않는다.

1. `sh scripts/impl-check.sh approve`를 돌린다.
   - 종료 코드 3이면 "기획이 없습니다. `/start`로 기획부터 하세요"라고 하고 멈춘다.
   - 종료 코드 4면 구현하지 않는다. 출력의 질문을 그대로 다시 보여 주고 "답하거나 `추천안대로`라고 답해 주세요"라고 하고 멈춘다. 답을 받으면 기획의 질문 아래에 `결정: <답>`으로 적고(`추천안대로`도 그대로 적는다) 다시 돌린다.
   - 0이면 스크립트가 "지금 하는 것"의 상태를 `구현 중 (승인 <YYYY-MM-DD HH:MM>, …)`으로 바꿨다. 바꾸지 못했다고 나오면 출력대로 손으로 고친다. 잠금이 없거나 보관 중(`/start`·`/end`가 보관한다)이면 핸드오프는 훅에 막히지 않는다.
2. 기획과 `### 추가 요청`에 적은 파일만 고치고 AGENTS.md의 검증 명령을 돌린다. 브라우저·Playwright 확인은 하지 않는다(검증 에이전트가 한다).
   - `.claude/skills/verify/SKILL.md`·`.agents/skills/verify/SKILL.md`는 읽지 않는다. 판정 기준에 맞춰 구현하지 않고 기획에 맞춰 구현한다. 그 파일은 검증 에이전트만 읽는다.
   - 실패하면 고쳐서 다시 돌린다. 기획 밖 파일을 고쳐야 풀리면 멈추고 그 파일과 이유를 말한 뒤 "기획을 고칠지 정해 주세요".
3. 검증 명령이 통과하면 검증 에이전트를 부른다. Agent 도구, `model: opus`, 프롬프트는 "`.claude/skills/verify/SKILL.md`를 읽고 그대로 따라 판정하고, 그 보고를 그대로 돌려줘"만 쓴다. 구현 내용이나 이 대화의 판단은 넣지 않는다.
4. 보고의 `판정:` 줄로 다음을 정한다.
   - `통과`·`확인 못 함 있음`: 아래 "`/end` 전에 확인할 것"대로 보고하고 끝낸다. 마일스톤을 `끝`으로 바꾸지 않는다(`/end`가 정한다).
   - `실패`이고 보고의 `회차`가 3의 배수가 아님: 보고의 고칠 곳만 고치고 검증 명령을 다시 돌린 뒤 3으로 돌아간다.
   - `실패`이고 `회차`가 3의 배수(3, 6 …): 멈추고 아래 "사람에게 넘기기"대로 보고한다.
5. 루프 중에는 기준 파일(`handoff/`·`milestones/`·`AGENTS.md`·`CLAUDE.md`·`.claude/`·의존성 파일·린트 설정·이미 있던 테스트)을 고치지 않는다. 훅이 막는다. 그 파일을 고쳐야 통과한다면 멈추고 그 파일과 이유를 말한다. `scripts/verify-loop.sh`는 부르지 않는다(검증 에이전트 전용).
6. 사람이 기획에 없는 것을 요청하면(구현 중이든 끝난 뒤든) 다시 기획하지 않고 추가 요청으로 받는다.
   - 구현하기 전에 "지금 하는 것"의 `### 추가 요청` 절(없으면 기획 표 아래에 만든다)에 한 줄을 쓴다: `| 추가-<번호> | <바꿀 파일> | <완료 조건(명령:·화면:)> | 요청 <YYYY-MM-DD HH:MM> "<사람이 한 말 요약>" |`. 사람이 이 대화에서 요청하지 않은 것은 적지 않는다.
   - 잠금 중이라 훅이 막으면 멈추고 "`! sh scripts/verify-loop.sh clear`로 잠금을 푼 뒤 다시 요청해 주세요"라고 안내한다. 잠금을 직접 풀지 않는다.
   - 쓴 뒤 2부터 다시 돈다.

`/end` 전에 확인할 것 (검증 보고에서 옮긴다. 새로 판단하지 않는다):
- 검증: `판정:` 줄과 회차. 검증 명령별 종료 코드
- 사람 확인: 보고의 "사람 확인" 그대로(띄우기 명령, 전체 URL, 할 동작 → 기대 결과)
- 확인 못 함(내 것): 판정 `실패`로 루프가 고치므로 여기까지 오면 보통 없다. 남아 있으면 기능 ID와 이유. 있으면 `/end`에서 `끝`이 되지 않는다
- 연결 남음: 기능 ID와 기다리는 것(담당). `/end`에서 `끝`을 막지 않고 마일스톤과 "다음에 할 것"에 남는다
- 추가 요청: `### 추가 요청` 줄 그대로와 각 줄의 검증 결과. 사람이 요청한 것이 맞는지 `/end`에서 확인받는다
- 이번에 안 한 것: 기획에서 "이번엔 안 함"인 기능 ID와 넘긴 곳
- 마지막 줄: "위 사람 확인을 마친 뒤 `/end`로 마무리하세요. `끝` 여부는 `/end`가 이 목록으로 정합니다"

사람에게 넘기기:
- "검증이 3회 실패해 멈췄습니다."
- 마지막 검증 보고 전체
- 회차별 실패 항목: `sh scripts/verify-loop.sh status`의 출력
- 다음 중 고르세요:
  - 직접 고친 뒤 `/verify`
  - 기획이 틀렸으면 `! sh scripts/verify-loop.sh clear`로 루프를 버리고 `/start`로 다시 기획
  - 원인이 보이면 그 원인과 "3회 더"라고 답하기

"3회 더"라고 답하면 그 원인부터 고치고 2부터 다시 돈다. 회차는 이어서 센다.
