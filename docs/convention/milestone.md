# 마일스톤 만들기

내 담당을 마일스톤으로 나눌 때 연다. 처음 한 번 만들고, 명세가 바뀌면 다시 만든다. 절차는 프론트·백엔드 저장소의 같은 문서와 같고, 이 저장소에는 **Python 몫(AI 서버가 하는 일)**만 적는다.

마일스톤 하나 = 화면 ID 하나. 같은 화면의 프론트 몫은 프론트 저장소, Java 몫은 백엔드 저장소의 마일스톤에 있다. 마일스톤은 번호 없이 화면 ID로 부른다. 화면 ID는 명세에 정해진 값이라 세 저장소에서 같다.

## 절차

1. 이니셜은 브랜치 이름이다(`/`가 있으면 앞부분). 아래 "담당" 표에서 내 줄을 찾는다. 없으면 멈추고 사람에게 묻는다.
2. DMS MCP의 `search_documents`로 담당 표에 나온 기능명세서를 찾는다(예: `AI매니저_기능명세서`). 같은 도메인 문서가 여럿이면 파일명 날짜가 가장 늦은 것을 쓴다.
3. `read_document`로 "기능 목록" 시트만 본다. 화면 ID 칸은 병합 셀이라 첫 행에만 값이 있다. 비어 있으면 위 행과 같은 화면이다.
4. 화면 ID별로 기능 ID와 기능명만 옮긴다. 기능 설명은 옮기지 않는다. 구현할 때 그 화면 것만 다시 읽는다.
5. "Python 몫" 표를 적용한다. 표에 Python 몫으로 나온 기능 ID만 마일스톤에 넣는다. 같은 명세의 나머지 기능 ID는 "제외"에 적고 어느 저장소 몫인지(프론트·Java)와 담당을 붙인다.
   - 같은 API나 같은 서버 동작을 쓰는 기능 ID는 처음 나오는 화면의 마일스톤 하나에 모은다(예: 컨텍스트 6턴 FN-AIM-011-15·002-11). 다른 화면의 기능 ID에는 "(화면은 SCR-…)"을 붙인다.
   - 화면 ID가 없는 공통 기반(`app/core`의 인증 검증·응답 껍데기 등)은 그것을 처음 쓰는 마일스톤에 "함께 만드는 것"으로 적는다.
6. "먼저 나와야 하는 것" 표에서 내가 기다리는 것을 마일스톤마다 적는다. 순서는 남이 기다리는 내 것이 든 마일스톤을 앞에, 그다음 기다리는 것이 적은 마일스톤을 앞에 둔다. 기다리는 것이 있어도 뒤로 미루기만 하고 빼지 않는다.
7. 마일스톤마다 완료 조건 후보를 1~2개 적는다(예: "mock 모드에서 `POST /internal/v1/ocr/receipt`가 `ReceiptOcrResponse` 모양을 돌려준다").
8. 읽은 기능명세서마다 "기능 목록" 시트의 기능 ID 수를 센다. 그 수는 마일스톤에 넣은 기능 ID 수와 "제외" 절에 적은 기능 ID 수를 더한 값과 같아야 한다. 다르면 빠진 기능 ID를 찾아 넣는다. 제외에는 이유(어느 저장소 몫인지, 담당)를 적고, 보고할 때 제외한 기능 ID를 빠짐없이 나열한다. 이유가 다른 기능 ID를 한 범위로 묶지 않는다.
   개수가 맞으면 내용을 확인한다: 같은 서버 동작이 두 마일스톤에 있지 않은가, 기능 ID가 그 마일스톤의 화면 ID 소속인가(아니면 "(화면은 SCR-…)"이 붙었는가), 제외 이유가 기능 설명과 맞는가.
9. `milestones/<이니셜>.md`에 아래 형식으로 쓴다. 공개 저장소이므로 비밀값과 개인 PC 경로를 쓰지 않는다. 커밋은 사람이 정한다.
10. `/start`가 부른 경우에는 멈추지 않고 `/start`의 다음 단계(마일스톤 고르기·기획)로 이어 간다. 따로 요청받아 만들었으면 보고 마지막 줄에 "`/clear` 한 뒤 `/start`로 첫 마일스톤을 시작하세요"라고 적는다.

화면설계서와 요구사항정의서는 이 단계에서 읽지 않는다. 마일스톤 하나를 구현할 때 그 화면 ID 부분만 찾아 읽는다.

```
# <이니셜> 마일스톤

기준: <기능명세서 파일명> (DMS, <확인한 날짜>)

## SCR-AIM-002 대화창 · 검색 질문/응답 — 대기
- 기능: FN-AIM-002-02 외부 AI API 호출 · 응답 표시, FN-AIM-002-07 …
- 함께 만드는 것: (공통 기반이 있을 때만) `app/core` JWT 검증 …
- 기다리는 것: LLM 제공자 결정 (팀)
- 완료 조건: …

## 제외
- FN-AIM-002-01: 프론트 몫(말풍선 표시, LJS 프론트)

## 대조
- AI매니저: 명세 138 = 마일스톤 N + 제외 M
```

상태는 `대기`·`진행`·`끝` 중 하나다. `끝`은 `/end`만 정한다(기준은 `.claude/skills/end/SKILL.md` 5번). 남의 API·화면을 기다려 연결만 남은 기능은 `끝`을 막지 않고 그 절의 `연결 남음:`에 남는다. 다음 작업은 `대기` 중 맨 위의 것을 고른다. "기다리는 것"은 순서를 정하는 참고일 뿐 막는 조건이 아니다. 외부 AI API가 정해지지 않았으면 mock으로 먼저 만들고 나중에 연결한다.

## Python 몫

| 기능 | Python 몫 | Python 몫이 아닌 것 |
